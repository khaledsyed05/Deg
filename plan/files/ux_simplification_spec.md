# ux_simplification_spec.md
## دق احجزلي — مواصفات تبسيط تجربة المستخدم

---

## 1. فلسفة الـ UX الأساسية

**قاعدة واحدة تحكم كل شيء:** إذا كانت الخطوة لا تقرب اللاعب من الحجز المكتمل، احذفها.

**ثلاثة مبادئ لا تنكسر:**
1. اللاعب يجب أن يرى الأسعار والتوفر قبل أي تسجيل
2. الحجز يجب أن يكتمل في أقل من 3 دقائق من أول تفاعل
3. الدفع لا يجب أن يحتاج أكثر من خطوتين بعد أول استخدام

---

## 2. أين الخطوات الزائدة حالياً

### رحلة اللاعب الحالية (مشكلة):
```
تسجيل → تأكيد OTP → إتمام الملف → اختيار المنطقة →
بحث → اختيار النادي → اختيار الملعب → اختيار الوقت →
اختيار المدة → اختيار طريقة الدفع → OTP الدفع →
تأكيد الدفع → تأكيد الحجز
```
= 13+ خطوة لأول حجز.

### رحلة اللاعب المطلوبة:
```
فتح التطبيق → رؤية الأسعار (بدون تسجيل) →
تسجيل سريع (رقم فقط) → اختيار الوقت →
دفع (Wallet بعد أول مرة) → تأكيد
```
= 5 خطوات بعد الإعداد الأولي.

---

## 3. ما الذي يجب حذفه أو دمجه

| العنصر الحالي | القرار | البديل |
|--------------|-------|--------|
| إتمام الملف الشخصي قبل الحجز | دمج | اطلب الاسم فقط عند أول حجز، بقية البيانات اختيارية |
| اختيار طريقة الدفع في كل حجز | تبسيط | احفظ الطريقة المفضلة، اعرضها افتراضياً |
| رسالة تأكيد الإلغاء بكتابة "cancel" | حذف | Confirmation dialog بسيط يكفي |
| فلترة معقدة في الكشف | تأجيل | اعرض فلاتر أساسية: الرياضة + المنطقة + التاريخ |
| Recurring booking في الإطلاق | تأجيل | Phase 2 |
| Review بـ 50 حرف minimum | تبسيط | Rating فقط + text اختياري بدون حد |
| WhatsApp/SMS choice screen | تبسيط | إذا WhatsApp متاح → أرسل له. إذا لا → SMS. بدون سؤال. |

## 4. أفضل flows للاعب

### Flow الكشف (بدون تسجيل — ضروري)
```
فتح التطبيق
→ عرض فوري للملاعب القريبة (بناءً على المنطقة المحددة أو GPS)
→ البطاقة تعرض: اسم النادي، الرياضة، أقل سعر متاح اليوم، بعد المسافة
→ Tap → تفاصيل النادي + الملاعب
→ Tap على الملعب → التواريخ المتاحة
→ إذا حاول الحجز → طلب تسجيل سريع
```

### Flow التسجيل السريع
```
رقم الهاتف
→ OTP (5 أرقام)
→ اسمك؟ (حقل واحد)
→ منتهي — ادخل للتطبيق
```
لا avatar، لا email، لا مدينة في هذه المرحلة. هذه تُجمع تدريجياً.

### Flow الحجز + الدفع (بعد التسجيل)
```
اختيار التاريخ والوقت
→ عرض السعر الكامل + خيار "دفع كامل / دفع عربون"
→ اختيار طريقة الدفع (أو Wallet إذا فيه رصيد)
→ دفع (OTP إذا MTN/Syriatel — Wallet = لحظي)
→ تأكيد فوري + notification
```

### Flow إعادة الحجز (الأهم)
```
من "حجوزاتي السابقة"
→ "احجز مجدداً" بجانب كل حجز مكتمل
→ يفتح مباشرة على نفس الملعب بنفس الوقت في أقرب تاريخ متاح
→ دفع بطريقة محفوظة
→ تأكيد
```
= 3 خطوات فقط.

## 5. أفضل flows للنادي

### Onboarding (تدريجي)
```
اليوم 1: بيانات النادي الأساسية (اسم، موقع، رقم هاتف)
اليوم 1: أول ملعب (اسم، رياضة، ساعات العمل، سعر)
اليوم 2: بعد أول حجز → شرح كيفية إضافة الملاعب التالية
اليوم 7: بعد أسبوع → إطلاق Dashboard الكامل تدريجياً
```

### إدارة يومية (أبسط ما يمكن)
```
Home Screen للنادي:
- اليوم: X حجز / Y متاح
- الإيراد اليوم: Z ل.س
- التنبيهات: هل في حجوزات جديدة؟
- زر واحد: "إضافة حجز يدوي" أو "إضافة وقت مغلق"
```

## 6. كيف ندعم الإنترنت الضعيف

- كل API response مضغوط ومصغّر
- الصور تُحمَّل بعد المحتوى
- Skeleton loading بدل spinning — يعطي شعور بالسرعة
- Timeout يطول لـ 15 ثانية قبل إظهار error
- آخر نتائج بحث تُخزَّن محلياً (local cache) لإعادة العرض بدون اتصال

---

## 7. كيف ندعم fallback channels

- كل حجز مؤكد يُرسل عبر SMS أيضاً (بدون FCM) — يصل حتى بدون إنترنت
- Club Admin يستطيع إضافة حجز يدوياً من مكالمة هاتفية (موجود في specs)
- إشعارات WhatsApp Baileys كبديل للـ FCM إذا كان الجهاز لا يدعمه

## UX GUARDRAILS

**قواعد صارمة — لا استثناء:**

1. **لا تطلب تسجيل قبل عرض الأسعار والتوفر.** اللاعب يرى المعلومة ثم يسجل.

2. **لا تجبر على دفع كامل مسبق دائماً.** خيار العربون يجب أن يكون متاحاً.

3. **لا تضيف feature جديدة إذا كانت تضيف خطوة لمسار الحجز الأساسي.**

4. **لا تسأل اللاعب عن نفس المعلومة مرتين.** إذا عرفت منطقته، لا تسأل مجدداً.

5. **لا تجعل الـ Dashboard أكثر من 4 أقسام ظاهرة في أول 7 أيام للنادي.**

6. **لا تجعل إلغاء الحجز يتطلب كتابة نصية.** Confirmation button كافٍ.

7. **لا تعرض بوابات الدفع كلها في كل مرة.** اعرض الأسرع/الأسهل أولاً بناءً على السجل.

8. **لا تجعل العروض last-minute تحتاج أكثر من 30 ثانية من النادي لإنشائها.**

9. **لا تجعل رحلة أول حجز أكثر من 3 دقائق.**

10. **لا تجعل اللاعب يخرج من التطبيق لإتمام أي خطوة إلا WebView الدفع.**
